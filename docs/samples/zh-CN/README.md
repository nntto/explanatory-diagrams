# 样例列表

本页列出 18 个样例及各自的使用场景。它们是 skill 中日语样例的简体中文版：布局与日语版相同，只翻译了文字。design-before-after 样例中嵌入的界面截图仍是日语。

skill 本身只包含日语样例和[日语列表](../../../skills/explanatory-diagrams/templates/README.md)。agent 从 [SKILL.md](../../../skills/explanatory-diagrams/SKILL.md) 找到这份列表，从中挑选相近的样例；目标文档是其他语言时，会翻译样例中的文字。本页不包含在 skill 中。

## 样例的分类

样例分为 3 类。

- **变更的展示方式**：变更前后的对比方式等，可以和任何类型的图组合使用的版式。
- **重构的说明**：把变更的展示方式套用到常见重构上的例子。
- **图的类型**：每种记法或题材一个样例，如架构图、时序图、状态机图。这些样例不展示变更前后。

例如，说明 AWS 架构的变更时，agent 用“AWS 架构图”的记法来画，再按“在一张图上叠加差异”的方式标出变化。

用图形画的样例都以同一个虚构的网店（订单、支付、发货）为题材。设计变化和色板的样例，以一个虚构杂货店管理后台的主题为题材，这个后台是为这些样例用 AntD 制作的。界面截图取自这个后台，源码在 [`tests/skill-evals/explanatory-diagrams/sources/mock-admin-ui/`](../../../tests/skill-evals/explanatory-diagrams/sources/mock-admin-ui/)。色板中变更前的值是 AntD 计算出的值。

样例中的题材、人名、数值和业务规则（如自动批准退款的金额、运费）都是虚构的。

所有样例都是 `.drawio.svg` 文件，可以用 draw.io 打开编辑。使用的颜色以及线条和符号的画法见 [references/drawio-style.md](../../../skills/explanatory-diagrams/references/drawio-style.md)（日语）。

## 变更的展示方式

### 左右并排对比

使用场景：想展示结构本身有什么不同的变更。变更前后共用同一个框架（本例中是各层的横带），让人一眼看出变化的部分。也写上“3 个 → 1 个”这样的数量变化。

![左右并排的变更前后图，展示从界面直接调用外部 API 的结构改为经由服务层的结构，标题为“将支付与库存回滚移至 OrderService，让界面只调用 1 个组件”](before-after-split.drawio.svg)

### 在一张图上叠加差异

使用场景：整体中只有一部分变化的变更。在变更后的图上，叠加新增的部分和删除的部分。本样例用蓝框标出新增的部分，用灰色虚线和 ✕ 标出删除的部分。

![在 AWS 架构图上叠加差异的图，标题为“将邮件发送交由 SQS 和 Lambda，无需等待发送即可返回响应”](before-after-diff.drawio.svg)

### 并排界面对比设计变化

使用场景：颜色、间距、圆角等外观上的变更。把变更前后的实际界面左右并排（横向很长的组件则上下排列），用框圈出需要关注的组件。给框编号，与列出变化值的表格对应。本样例的框是橙色的。

![左右并排的变更前后界面，标题为“将日期范围填充、聚焦轮廓和 link 颜色统一为店铺颜色”](design-before-after.drawio.svg)

### 对比变更前后的色板

使用场景：一并修改主题颜色色阶（背景、边框、填充、文字）的变更。把色阶按列对齐，只对要修改的颜色，把变更前和变更后的行上下排列。不修改的颜色只列一次，用框圈出有问题的色阶和修改后的值。本样例用橙框圈出有问题的色阶，用蓝框圈出修改后的值。

![对比变更前后的色板，标题为“自定义主色的 10 个色阶，消除灰色色阶”](palette-before-after.drawio.svg)

## 重构的说明

### 移动状态的存放位置

使用场景：把 Hook 或模块持有的状态提取到别处的重构。标出要移动的状态和移动后的位置，并注明状态的数量不变。本样例把要移动的状态画成橙色，把移动后的位置画成蓝色。

![左右并排的变更前后图，标题为“从 useOrderEditor 提取 3 个状态并移至 useDraft”](refactor-move-state.drawio.svg)

### 统一名称

使用场景：只修改名称的重构。把名称按部分拆开排成表格，标出不符合规则的名称和新名称。也列出调用方需要修改的地方。

![统一名称的图，标题为“按命名规则将 useOrderEditSave 统一为 useOrderSave”](refactor-rename.drawio.svg)

### 提取并公开函数

使用场景：把封闭在文件内部的函数提取出来并公开的重构。现有的使用关系用实线表示，后续 PR 中接入的使用方用虚线表示。

![左右并排的变更前后图，标题为“将订单与表格转换函数提取到 orderTableConverters.ts 并公开”](refactor-extract-module.drawio.svg)

### 共享状态

使用场景：把各组件分别持有的状态，在处理同一数据的组件之间合并为一个的重构。用状态数量的不同（3 个 → 1 个）表示变化，并用虚线保留移动前的位置。

![左右并排的变更前后图，标题为“将各表格的保存中状态合并为每个订单一个并共享”](refactor-share-state.drawio.svg)

### 删除复制后一路传递的值

使用场景：在跨多个阶段的处理中，删除复制后一路传递的值，让所有处理都读取原来的值的重构。把数据、读取的处理和结果分成横带，把变更前和变更后叠加在一张图上。本样例用橙色虚线和删除线表示删除的内容，用蓝色表示新读取的值以及因此变化的值。

![把变更前后叠加在一张图上，标题为“删除复制并流转的 display_name，直接读取 name”](refactor-remove-duplicate.drawio.svg)

## 图的类型

### AWS 架构图

使用场景：说明服务的部署位置和冗余方式。使用 AWS 的图标和分组（区域、VPC、AZ、子网），并给请求的流程编号。

![AWS 架构图，标题为“将订单 API 部署在 2 个 AZ，即使其中一个停止也能接收订单的架构”](aws-architecture.drawio.svg)

### 时序图

使用场景：按顺序说明多个参与者之间的交互。区分使用同步调用、异步消息和响应的箭头，并使用激活条和 alt 框。

![时序图，标题为“从订单确认、外部支付到 Webhook 结果通知的流程”](sequence.drawio.svg)

### 状态机图

使用场景：说明状态，以及使状态转移的事件、条件和处理。转移的标签按“事件 [条件] / 处理”的顺序书写。

![状态机图，标题为“订单状态：从待付款到送达、取消或退货的流转”](state-machine.drawio.svg)

### C4 容器图

使用场景：说明构成系统的应用、DB、外部服务，以及它们之间的关系。在关系线上写明“做什么”和“[技术]”。

![C4 容器图，标题为“连接 Web 应用、管理后台、订单 API 与外部系统的容器架构”](c4-container.drawio.svg)

### ER 图

使用场景：说明表、列、键，以及表之间的行数关系。在图例中说明鸦脚记法各符号的含义，并用注释记下设计上的判断。

![订单、明细、支付等各表，标题为“展示客户、地址、订单、明细、商品与支付关系的 ER 图”](er-diagram.drawio.svg)

### 业务流程（BPMN）

使用场景：说明各负责角色的工作和分支。用泳道区分负责角色，用标记区分人工操作和系统处理。

![业务流程图，标题为“从买家退货申请、自动审批判定、质检到退款的业务流程”](business-flow.drawio.svg)

### 欧拉图（集合与元素）

使用场景：说明由条件组合决定的对象。把集合画成圆，元素画成点，并附上每个元素的判定表。

![欧拉图，标题为“从已订阅且邮箱有效的会员中排除退订者的邮件收件人”](euler-sets.drawio.svg)

### 组件与状态

使用场景：说明界面的状态由哪里持有、由谁读写。用边框（实线、虚线、点线）区分状态的种类。

![组件树与状态的存放位置，标题为“订单编辑各组件与 Store 的状态归属及读写流程”](state-ownership.drawio.svg)

### 代码与运行时的值

使用场景：说明执行的行或返回的值随输入而变化的处理。把代码的每一行和按各个输入求得的值放在同一高度。

![代码与 3 种输入下求得的值，标题为“计算运费的 shippingFee 条件判断及 3 种输入的执行流程”](code-trace.drawio.svg)
