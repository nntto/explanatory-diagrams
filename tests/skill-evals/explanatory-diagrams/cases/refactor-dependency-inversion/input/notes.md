# 出荷の処理から SDK の直接呼び出しを外す

## 背景

- 出荷の処理（`src/shipping/shipOrder.ts`）は、配送業者・ストレージ・メールの SDK を直接 import し、モジュールの読み込み時にクライアントを作っている。
- そのため、テストでは 3 つの SDK を `vi.mock` でモジュールごと差し替えている。SDK の版を上げてクラスの形が変わるたびに、モックを直してきた。
- 来月、2 社目の配送業者を足す。今の形のままだと、出荷の処理の中に配送業者ごとの分岐が入る。

## 変更

- 出荷の処理が外に頼むこと（送り状の発行、ファイルの保存、メールの送信）を、`src/shipping/ports.ts` に interface として置いた。
- SDK を使う実装は `src/infra/` に移した。3 つの SDK のクライアントは `src/main.ts` で作って渡す。
- テストは SDK のモックをやめ、interface の偽物を渡す形にした。
- 振る舞いは変えていない。送り状の内容、PDF の保存先、メールの文面は前と同じ。
- 注文の読み書き（`src/orders/orderStore.ts`）は、この PR では触っていない。
