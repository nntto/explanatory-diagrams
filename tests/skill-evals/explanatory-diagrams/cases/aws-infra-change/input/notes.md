# 商品画像を S3 に置き、CloudFront から配信する

## 背景

管理画面で商品画像を登録すると、API（ECS の Fargate タスク）が画像を受け取って EFS に保存していた。EC の商品ページや管理画面に出す画像も、API が EFS から読んで返していた（`https://api.example.com/images/...`）。

- 数 MB の画像をメモリに載せてから EFS に書くので、タスクのメモリを 2 GB にしていた。アップロードが回線の都合で途中で止まると ALB に切られるので、ALB のアイドルタイムアウトも 300 秒に延ばしていた。
- 画像を返すのも API なので、商品一覧のように画像が多いページほど API の負荷が上がる。キャッシュもない。
- サムネイルがなく、一覧にも元の画像をそのまま出していた。

## 変更

- 管理画面は API から S3 の署名付き URL（PUT、有効期限 5 分）をもらい、ブラウザから S3 の `originals/` に直接アップロードする。URL は API のタスクロールで署名するので、タスクロールの権限を EFS から S3（`originals/*` への `s3:PutObject`）に替えた。
- `originals/` に画像が置かれると Lambda が動き、幅 400px のサムネイルを `thumbnails/` に置く。
- 画像は CloudFront から配信する。バケットは公開せず、配信では CloudFront だけが OAC で読む。API は画像の URL を CloudFront のドメインで返す（`IMAGE_BASE_URL`）。
- EFS（ファイルシステム、アクセスポイント、2 つの AZ のマウントターゲット、セキュリティグループ、バックアップの設定）と、ECS タスクのボリュームを消した。ALB のアイドルタイムアウトは既定の 60 秒に戻し、タスクのメモリは 1 GB にした。
- VPC、サブネット、NAT ゲートウェイ、RDS は変えていない。

API のコードの変更（署名付き URL を返すエンドポイントの追加と、`/images/*` の削除）は別の PR にした。EFS にある今の画像は、S3 を先に作って `originals/` に写してから EFS を消す。

## ファイル

- `infra.diff`：変更前から変更後への Terraform の差分
- `infra/`：変更後の Terraform 一式
